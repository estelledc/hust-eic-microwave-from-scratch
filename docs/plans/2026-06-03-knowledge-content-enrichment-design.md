## 内容设计

每页新增或完善三类助学内容。

### 作业怎么答

给出 3-5 步答题顺序，目标是把“概念理解”翻译成“卷面怎么写”。每一步必须对应本页已有概念或已校验题解口径，例如先判波型、再写边界条件、再写截止或导行条件、最后做单位和物理合理性检查。

### 卡点急救

用小表格列出常见卡点、可能原因和修正动作。卡点只覆盖本节高频错误，不扩展成全阶段错题表。典型行包括：

- 概念分不清：回到定义句或对照表。
- 公式能背但不会用：先检查前提，例如无耗、均匀、`f>f_c`、TE/TM 下标是否合法。
- 结果和题解不一致：检查坐标方向、波长口径、端口或参考面。

### Mini 自检强化

对只有 1 道自检题的页面扩展到 2-3 道。答案必须完整，不能只写提示。题目以短问答为主，避免引入长计算，重点训练口述表达、条件判断和错因定位。

## 事实边界

新增内容仅使用以下来源：

1. 当前知识点页中已经写明的公式和定义。
2. 已校验作业解答及其符号导读。
3. `docs/KNOWLEDGE_AUDIT.md`、`docs/QUESTION_AUDIT.md`、`docs/AUDIT_NOTES.md` 中已经确认的反查口径。
4. 必要课程常识，但只用于解释已出现的结论，不新增教材外推导。

不新增未经验证的数值答案、教材页码或课件原文。涉及模式计数、简并、导行条件和波长比较时，以现有题解口径为准。

## 结构与数据流

本项目是 Markdown 内容源加静态构建脚本。正文源文件位于 `content/knowledge/`，`build.py` 负责生成 `site/`。本轮只修改 Markdown 内容，不改构建脚本、样式、配图脚本或站点交互代码。

每个单讲页的数据流保持不变：

1. 读者从阶段 README 或首页进入单讲页。
2. 单讲页先提供直觉解释和核心公式。
3. 新增助学栏目把核心公式连接到作业答题流程。
4. 文末相关链接继续指向对应作业解答或相邻知识页。

## 错误处理与质量控制

内容写作时重点避免三类错误：

- **口径冲突**：同一公式的前提、坐标方向、波长定义必须和现有题解一致。
- **重复堆砌**：新增栏目只补读者做题所需的步骤和错因，不复写整页正文。
- **链接断裂**：新增或保留的作业链接必须通过交叉引用检查。

## 验证方案

完成正文扩充后运行：

```bash
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python build.py
python3 scripts/tools/check_cross_refs.py
```

再抽查新增段落是否满足：

- 每个处理页至少新增或完善“作业怎么答”。
- 第一批处理页中需要时新增“卡点急救”。
- Mini 自检答案完整，且不引入未定义符号。
- 构建通过，交叉引用缺失为 0。
